# 例行：AI 公司突发重置监测

- 日程：`@every 30m`
- 时机：灵活，可提前或延后最多 15 分钟
- 技能：每次运行按「AI 公司额度重置监测」执行

以下是例行的任务说明，导入或自建时按用户时区和通知对象稍作调整即可。

---

你负责监测各家「突发重置」并维护监测记录：官方在正常周期之外，额外给用户重置、加赠或发放可储蓄的一次性额度。每次运行时按「AI 公司额度重置监测」技能检查下列已核实账号（只按公司向用户展示，不要把完整账号名单当作日常展示内容）。

按公司监测：

- ChatGPT（OpenAI）：OpenAI、OpenAIDevs、OpenAINewsroom、ChatGPT、thsottiaux（Tibo，OpenAI 员工，Codex 与 ChatGPT Work 额外重置的主要宣布人，必须监测；只收重置、加赠、可储蓄额度，以及高度疑似的重置预告；排除与重置无关的日常更新）。注意官方产品号是 @ChatGPT，旧 handle @ChatGPTapp 已不存在。这类重置多针对 Codex / ChatGPT Work，统计和展示时要标明范围。
- Grok（xAI / SpaceXSI，含 Grok Bot）：SpaceXSI、grok、bot、elonmusk（只收与 Grok 或额度相关的帖）、SuperGrok、cursor_ai（只收与 Grok 或 Grok Bot 额度相关的帖）。公司号原 @xai 已改名为 @SpaceXSI，不要把已被占用的空号 @xai 当作官方号。@grok 和 @bot 回复量极大，只收原创公告，排除回复和自动回复。
- Claude（Anthropic）：AnthropicAI、claudeai、ClaudeDevs（官方开发者号，额外重置的主要宣布人，必须监测）、lydiahallie（员工，曾宣布 Max 周额度重置，只收重置相关）、alexalbert__（员工，会宣布或转发重置，只收重置相关）。

分类如下，不要混在一起：

- 正式宣布：明确说正在重置、已经重置，或发放可储蓄重置。计入正式次数。
- 高度疑似：来自上述监测账号，虽未正式宣布，但强烈暗示即将或可能有一次额外重置的预告、暗示或口头安排。必须标成「疑似」，单独列出，不计入正式次数。若之后出现对应的正式宣布，把这条疑似改成已确认，不要重复计数。不要收录路人猜测、毫无重置含义的玩笑，或常规提额、限期加倍、套餐改价、自动回复。同一事件被多人转发只计一次，归到对应公司。

同时维护按公司的量化统计（时间用用户本地时区，并标明时区）：正式突发重置的次数、平均间隔、最长间隔、最近一次时间；即时到账和可储蓄重置尽量分开计。疑似条数单独统计，不要算进正式次数。

如果发现新的正式宣布或新的高度疑似：更新已有监测记录和统计，按公司归类，疑似必须明确标记为「疑似」；然后在本对话通知用户，说明是哪家、何时、是正式还是疑似、公告要点、原帖链接，以及更新后的正式次数和最近一次时间。

如果既没有新的正式宣布、也没有新的高度疑似：不要给用户发消息，也不要仅为更新「上次检查时间」而改数据或打扰用户。

结果发给本对话里的用户。没有新的正式宣布也没有新的疑似时保持安静，不要发任何消息。
