# AI 公司额度重置监测

监测 AI 公司在正常额度周期之外，额外给用户重置、加赠或发放可储蓄的一次性额度。这是一套可复用流程：任何 Grok Bot 都可按它检查 X、分类、统计并通知用户。定时执行由例行触发，不要把开关时间写进本技能。

## 目标

- 主目标：突发/额外重置（正常周期之外的重置、加赠、可兑换或可储蓄一次性额度）。
- 次要：用户各服务的正常额度恢复。必须按服务单独授权，未授权不查、不编造用量数字。
- 展示口径按公司归类，不要把完整监测账号名单锁在用户常见的看板里。用户主动要求汇报账号时可以在对话里说。

## 默认监测范围

默认三家，可按用户要求增删。增加新公司时，不要只登官方公司号：要找实际会宣布额外重置的员工号和产品号，用资料、认证和历史宣布核实归属。

## 分类（不要混在一起）

- **正式宣布**：明确说正在重置、已经重置，或发放可储蓄重置。计入正式次数。尽量区分即时到账（applied）与可储蓄/后续兑换（banked）。
- **高度疑似**：来自上述监测账号，虽未正式宣布，但强烈暗示即将或可能有一次额外重置的预告、暗示或口头安排。必须标成「疑似」，单独列出，**不计入正式次数**。若之后出现对应的正式宣布，把这条疑似改成已确认，不要重复计数。
- **不算**：路人猜测、毫无重置含义的玩笑、常规提额、限期加倍、套餐改价、产品发布、自动回复。
- 同一事件被多人宣布或转发只计一次，归到对应公司。用稳定的事件标识去重，附加帖可标为重复而不单独计次。

## 统计

- 时间用用户本地时区，报告时标明时区名称。若用户未说明，用对话环境里的用户时区。
- 按公司在内部维护：正式突发重置的次数、平均间隔（少于 2 次则留空）、最长间隔、最近一次时间。即时到账与可储蓄尽量分开计。
- 疑似条数单独统计，不要算进正式次数。
- 间隔分布很不均匀时，在内部可分段记录，不要用一个容易误导的总平均冒充。这些分段细节不要写进日常通知；只在用户明确询问间隔分布时，用尽量短的几行说明起止点。
- 统计窗口要在内部记下。新用户的可核验历史窗口先保存，之后按新事件递增。初次向用户汇报时，每家最多一两行（正式次数、最近一次，必要时注明额度范围），不要展开完整历史或分段分析。
- 不要编造公告、数字、帖 ID 或链接。没有原帖链接就不要挖一个。第三方汇总只作为索引，能用 X 原帖核对的就核对。

## 如何检查 X

- 使用 Grok Bot 自带的公开 X 读取能力（用户无需另外连接 X 账号也可以查公开帖和用户资料）。遵守读取频次上限。
- 先核对账号是否仍是对的那个（handle 会改名），再搜这些账号的原创帖，用帖 ID 核对正文和时间。
- 正常运行时以上次已看过的时间为起点，避免重复劳动；首次或补全历史时再拉长窗口。
- 已知的高度疑似要在后续运行里跟进：若时间已过还没正式宣布，保留疑似；已确认则转正式且不重计。

## 通知

通知必须轻量化、结构化，只留必要信息。初次检查、例行通知和用户询问，都用同一套格式。

每条事件写成下面这样的短块，按公司分组；多条之间空一行：

**{公司} · {正式宣布|高度疑似}**
{日期时间}（{时区}）
{一句话要点：说清发生了什么，不要引用或转述原文。额度类须注明范围（如 Codex / ChatGPT Work），以及即时到账或可储蓄。}
[来源]({url})

额度类通知在该事件块后再加一行摘要：`{公司} 正式 {N} 次{必要时注明范围}，最近一次 {日期}{即时到账或可储蓄}`。不要在每次通知里展开历史分段、平均间隔或长段统计。

来源只附链接：写成行内 Markdown，例如 `[来源](https://x.com/...)`。不要把原帖或页面正文贴进对话，不要单独一行裸贴 URL（以免展开成帖子卡片），不要写「原帖在这里」后再跟引用块或嵌入。没有可靠链接就省略来源行，不要编造。

- 发现**新的正式宣布**或**新的高度疑似**：按上面格式通知。
- **既没有新的正式宣布、也没有新的高度疑似**：不要发消息，也不要仅为更新「上次检查时间」而打扰用户。
- 用户主动询问时，用同一套短格式报告尚未确认的疑似，以及每家一两行的正式统计；这不受上面「保持安静」约束。用户明确问间隔分布时，才用尽量短的几行补充。

## 正常额度（可选、单独授权）

- 不要收集密码、令牌或会话。用户明确要为某家服务授权之后，再按该服务可用的正规途径查剩余用量和下次重置时间。
- Grok / Grok Bot 的用量可以在用户授权后，用 Grok Bot 自身的用量查询能力来看。ChatGPT、Claude 等若没有可用的官方连接器或用户授权的查询途径，实话说明，不要编造数字。

## 扩展

要加新的公司时：核实官方号（小心改名和被占用的同名号），再找会宣布额外重置的员工或产品号，把归属、handle 和只收什么写进例行与本技能的监测清单，仍按同一套分类与统计规则处理。
