# AI 新模型预告监测

监测用户勾选的 AI 公司，在官方渠道发布或预告的新模型、新版本和重要模型预告。这是一套可复用流程，与「AI 公司额度重置监测」分开：节奏是每天一次，范围是中美会发新模型的公司，分类规则也不同。定时执行由例行触发，不要把开关时间写进本技能。已核实的账号、排除项和官网补充见配套文档 [`docs/model-watch.md`](../docs/model-watch.md)。

## 目标

- 盯新模型、新版本、公开预览，或已经公开档期的正式预告。
- 只监测用户在「监测配置」里勾选的公司。完整目录可以比较长，不要在未选择时默认全开。
- 日常通知按公司归类，不要把完整账号名单当作日常展示主体。

## 监测配置

配置在与用户的对话里完成（这就是监测配置入口），写入记忆，例行只看已勾选的公司：

- 初次设置时，列出默认目录，按地区分组，让用户勾选要监测新闻的模型厂；可以少选、全选，或一个都不选。不要替用户默认全选。
- 用户之后说「改监测配置」「打开监测配置」或要增删公司时，用同样方式再列一次当前勾选，让用户改，并更新记忆。下一轮例行按新选择执行。
- 还没有勾选记录时，不要自行开始自动监测；先问用户选哪些公司。
- 默认目录（可按用户要求增删，但增删的是可选目录，不等于已勾选）：
  - 美国：OpenAI、Google DeepMind、Anthropic、xAI、Meta、Microsoft、Amazon
  - 中国：阿里（通义）、字节（豆包）、百度（文心）、腾讯（混元）、华为、DeepSeek、月之暗面（Kimi）、智谱、MiniMax
- 检查前先核对 handle 仍指向原来的账号。用户 ID 是稳定主键。

## 分类（不要混在一起）

- **正式**：官方明确发布新模型或新版本，或给出可核验的正式预告（名称、档期或获取方式已经公开）。
- **高度疑似**：来自监测账号、尚未正式宣布，但强烈暗示即将有新模型或新版本。标成「疑似」，单独列出；之后正式宣布则改为已确认，不要当两条独立新闻重复通知。
- **不算**：路人猜测、毫无模型含义的玩笑、纯粹定价或套餐改价、额度重置（那是另一条监测线）、招聘、常规活动运营、自动回复、第三方模型上架到某家云平台。
- 同一事件被多人宣布只计一次，归到对应公司。

## 如何检查

- 使用 Grok Bot 自带的公开 X 读取（用户不必另连 X）。遵守频次上限。先核对账号，再看自上次检查以来的原创帖，用帖 ID 核对正文和时间。回复量大的号只收原创公告。
- 若某家主要在官网或博客发布、X 上很少发：在用户勾选了这家时，检查文档里已经核实过的官方博客或新闻页；打不开或无法核实就不要编。
- **不要假装能读取微博或微信公众号**，除非当时已有可用的正规途径。国内厂商若主要在那些渠道先发，只监 X 和已确认官网会有遗漏，向用户说明即可。
- 华为：X 不是主渠道。勾选华为时，以配套文档里已确认的官网新闻页为主，不要把公司 X 号当全量来源。
- 字节跳动：尚未核实到可信的豆包消费级官方 X 号。默认看 Seed 实验室号（`@ByteDanceSeed_`）和已确认的 Seed / 豆包官网。
- Amazon：Nova 等第一方模型会夹在大量 AWS 新闻和第三方上架信息里，必须过滤，只收第一方模型。
- DeepSeek、百度：官方 X 有号但不是全量，勾选时应同时看已确认的官网新闻或博客。
- 正常运行以上次已看过的时间为起点；每天一次即可。时间用用户本地时区，报告时标明时区。不编造公告、数字、帖 ID 或链接。

## 通知

通知必须轻量化、结构化，只留必要信息。初次检查、例行通知和用户询问，都用同一套格式。

每条事件写成下面这样的短块，按公司分组；多条之间空一行：

**{公司} · {正式|高度疑似}**
{日期时间}（{时区}）
{一句话要点：说清发布或预告了什么，不要引用或转述原文。}
[来源]({url})

来源只附链接：写成行内 Markdown，例如 `[来源](https://x.com/...)` 或 `[来源](https://...)`。不要把原帖或官方页面正文贴进对话，不要单独一行裸贴 URL（以免展开成帖子卡片），不要写「原帖在这里」后再跟引用块或嵌入。没有可靠链接就省略来源行，不要编造。

- 有新的正式发布/预告或新的高度疑似：按上面格式通知。
- 没有新消息：不发消息，不为「上次检查时间」打扰用户。
- 用户主动询问时，用同一套短格式报告近期情况和尚未确认的疑似；这不受上面「保持安静」约束。

## 扩展

要往目录加公司：核实官方号（小心改名和冒名），确认会实际宣布新模型，写入配套文档和可选目录；仍要用户在监测配置里勾选后，才开始监测这家。
